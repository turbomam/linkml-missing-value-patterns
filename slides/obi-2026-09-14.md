# Missing data in LinkML and OBO

## Allowing, blocking, constraining and explaining absent values

OBI Development Call, 2026-09-14
Mark Andrew Miller, Lawrence Berkeley National Laboratory

Repository: https://github.com/turbomam/linkml-missing-value-patterns

<!-- Every measured claim here was run on 2026-09-14 against linkml 1.11.1 unless a slide says otherwise. -->

---

## The question

A field is **mandatory** and **strongly typed**: `depth_m`, with LinkML range `float`.
A negative control sample has no depth. The submitter can:

1. drop the record, so the sample disappears
2. write `depth_m: not collected`, which fails validation, or poisons consumers if the range was a string
3. leave it blank, so "does not apply" and "we forgot" look the same

**Can a schema keep the field required and typed, and still let a submitter say why it is empty?**

---

## One type, several vocabularies

| Where | `depth_m` with range `float` becomes |
|---|---|
| LinkML metamodel, `linkml:types` | `uri: xsd:float`, `exact_mappings: [schema:Float]`, Python base `float` |
| JSON Schema | `"type": "number"` |
| OWL | `owl:DatatypeProperty`, `rdfs:range xsd:float` |
| SHACL | `sh:datatype xsd:float`, `sh:minCount 1` |
| Pydantic | `depth_m: float` |
| SQL DDL | `depth_m FLOAT NOT NULL` |

The metamodel maps `float` only to `xsd:float` and `schema:Float`. `double` is `xsd:double` with `close_mappings: schema:Float`.

Run: `just float-type` (linkml 1.11.1)

---

## Absence is lost in both stacks, for opposite reasons

| | LinkML dataset | OBO / RDF graph |
|---|---|---|
| Default form of a missing value | the key is not there | no triple is written |
| What a reader can conclude | only that the field is empty | nothing (open world) |

The fix is the same in both: **state the absence as an assertion.**

---

## Reasoning and validation disagree about a missing required value

Same individual, no depth, class requires at least one:

| Tool | Axiom or shape | Result |
|---|---|---|
| HermiT (ROBOT 1.9.10) | `DataMinCardinality(1 hasDepth)` | **consistent** |
| pyshacl 0.40.1 | `sh:minCount 1` | `sh:conforms false` |
| LinkML `linkml-validate` | `required: true` | `'depth_m' is a required property` |

OWL can reject a value that must **not** be there (`max 0`, `NegativeDataPropertyAssertion`, Wikidata's `wdno:` complement class). It cannot reject one that is merely missing.

Run: `just open-world`

## INSDC already has a vocabulary, and a usage rule

```
not applicable     -> control sample, sample group
missing
  not collected     -> synthetic construct, lab stock, third party data
  not provided      -> data agreement established pre-2023
  restricted access -> endangered species, human-identifiable
```

- Use the terms **only for mandatory fields**. Optional fields are left empty.
- The table files control sample and sample group under **not applicable**. The usage rule still prefixes all eight reporting-level terms with `missing: `.
- NCBI BioSample attribute values (local copy, submissions through 2026-05-10): `missing: control sample` 37,073; `not applicable: control sample` 483. Submitters follow the prefix rule.

https://www.insdc.org/technical-specifications/missing-value-reporting/

## GENEPIO datum status

```
IAO:0000027 data entity
  GENEPIO:0001850 datum status
    GENEPIO:0001618 missing
      GENEPIO:0001620 not collected     GENEPIO:0001668 not provided
      GENEPIO:0001810 restricted access GENEPIO:0001662 in process
    GENEPIO:0001619 not applicable
    GENEPIO:0001851 recorded
```

"datum status": *a data item which is about the collection state of a datum at some point in time.*

- Under IAO `data entity`. DataHarmonizer `NullValueMenu` value sets use these terms as `meaning:` targets.
- Includes reasons (not collected, restricted access) and states (in process, recorded).

## OBI draft: incomplete data records

<!-- _class: small -->

Sebastian Duesing's "Incomplete Data Items" slides, revised hierarchy v2, unchanged since 2026-08-31. Definitions paraphrased.

```
data record
  incomplete data record           no data entity is stored
    missing data record            could fit the record, but no value is stored
      not available data record    may have been determined, but is not available
      unknown data record          not determined
    not applicable data record     cannot be determined, because it does not make sense
  other data record                a value outside the allowed options
  syntactically incorrect record   (definition not yet written)
```

---

## The draft classes in LinkML terms

| Draft class | Closest handling in LinkML | Shown by |
|---|---|---|
| not applicable | a schema fact: `value_presence: ABSENT` in `slot_usage` or a rule | CDISC ARS schema |
| unknown, not available | a reason term with `meaning:` (options 1, 2, 3) | `just option1`, `option2`, `option3` |
| other | not missing: a value outside the value set | open enum `any_of: [Enum, string]` |
| syntactically incorrect | `depth_m: not collected` in a float slot is rejected | `just option0` |
| about the information system (draft slide 9) | a separate report record (option 4) | `just option4` |

## What LinkML offers today

<!-- _class: small -->

| Want to | Metaslot | Works? (1.11.1) |
|---|---|---|
| block absence | `required: true` | yes |
| warn on absence | `recommended: true` | only with `RecommendedSlotsPlugin` in a validation config; off by default from 1.8.7 to `main` (`just recommended`) |
| forbid a value in context | rule with `value_presence: ABSENT` | yes, but `value_presence` is marked **unstable** |
| mark a slot inapplicable | `inapplicable` | **implemented nowhere** |
| fill a default | `ifabsent` | generated Pydantic and Python classes fill it when an object is built; `linkml-validate` and JSON Schema ignore it (`just ifabsent`) |
| accept a value or a reason | `any_of: [range: float, range: ReasonEnum]` | validates |
| give a reason an IRI | enum `meaning:` | yes |

No LinkML condition can test whether a value is **null**. A key holding null counts as PRESENT.

## Six ways to keep the field required and typed

| Option | Shape | Stays `required` | Strong range | Flat table |
|---|---|---|---|---|
| 0 strict | no escape hatch | yes | yes | yes |
| 1 / 1b union | `any_of` / `exactly_one_of` real range or reason | yes | no | yes |
| 2 value object | object holds a value **or** a reason | yes | yes | no |
| 3 sibling column | optional value plus `*_missing_reason`, tied by rules | via rules | yes | yes, +1 column |
| 4 out of band | separate `MissingValueReport` records | no | yes | yes |

Option numbers are the schema file names, `src/schema/option0_strict.yaml` through `option4_out_of_band.yaml`; 1b is option 1 written with `exactly_one_of`.

`just option0` ... `just option4` validates that option's valid and invalid examples; `just check` runs all 23. Same results on linkml 1.8.7, 1.9.6, 1.10.0, 1.11.1 and `main`.

## Production schemas already do this

| Schema | Pattern | Measured 2026-09-14 |
|---|---|---|
| [DataHarmonizer Canada COVID-19 3.0.1](https://github.com/cidgoh/DataHarmonizer/blob/HEAD/web/templates/canada_covid19/schema.yaml) | `any_of: [string, NullValueMenu]`, GENEPIO meanings | 77 slots, 32 required |
| [DataHarmonizer PHA4GE 1.0.5](https://github.com/cidgoh/DataHarmonizer/blob/HEAD/web/templates/pha4ge/schema.yaml) | same | 52 slots, 12 required |
| [CDISC Analysis Results Standard](https://github.com/cdisc-org/analysis-results-standard/blob/HEAD/model/ars_ldm.yaml) | subclass slots `NOT USED` with `value_presence: ABSENT` | 32 uses |
| [Pan-Canadian Genome Library](https://github.com/Pan-Canadian-Genome-Library/data-dictionary/blob/HEAD/base/base.yaml) | "Missing - Not collected" etc. inside enums | 31 of 50 enums, no `meaning:` |
| [NF Data Portal](https://github.com/nf-osi/nf-metadata-dictionary) | "Not Applicable" in value sets, rules exempt it | 7 value sets |
| [linkml/valuesets](https://github.com/linkml/valuesets/blob/HEAD/src/valuesets/schema/bio/insdc_missing_values.yaml) | `InsdcMissingValueEnum`, FHIR `DataAbsentEnum` | NCIT mappings mixed |

Option 1 (the union) is the one in widest use. Option 3's "not applicable is a schema fact" is in a CDISC standard.

## Completeness is relative to a schema

Same file, two schemas:

```
$ linkml-validate -s src/schema/option1_union.yaml  -C Biosample data/option1/valid_depth_reason.yaml
No issues found

$ linkml-validate -s src/schema/option0_strict.yaml -C Biosample data/option1/valid_depth_reason.yaml
[ERROR] 'not applicable' is not of type 'number' in /depth_m
```

Neither validator is wrong. "Incomplete" is a relation between a record and a schema, which is why a record can be complete in one system and incomplete in another.

## The same record as a table and as a graph (option 3)

```
sample_id  depth_m  env_broad_scale    depth_m_missing_reason
SAMP:0302           terrestrial biome  unknown
```

```turtle
SAMP:0302 a mvp:Biosample ;
    mvp:depth_m_missing_reason NCIT:C157157 ;
    mvp:env_broad_scale ENVO:00000446 .
```

The submitter types a label. The graph gets an IRI. **`meaning:` is where an OBO term plugs in.**

Built with `just convert` (`gen-owl`, `linkml-convert`). Outputs in `generated/`.

## What does not survive conversion

| | OWL | TSV | Turtle |
|---|---|---|---|
| options 0, 2, 3, 4 | yes | yes | yes |
| options 1, 1b (union) | malformed union | **fails** | **fails** |

- Union: TSV `Value of depth_m ... is not a dict`; Turtle `Unknown CURIE prefix: @base`; JSON-LD writes RDF **without error** but types `12.5` as `mvp:@id`.
- `gen-owl` keeps the union as a datatype whose union includes a class; the property range stays `xsd:float`. OWL 2 DL cannot make one property hold both a number and a term IRI.
- `gen-owl` ignores `value_presence`: "absent requires a reason" becomes a present-value axiom.
- `gen-owl` asserts `NCIT:C48660 rdfs:subClassOf mvp:MissingValueReasonEnum`, adding a parent to an external term.

The most widely used pattern is the one that cannot leave YAML.

## Null, and what is moving in LinkML

- **"Are required slots nullable?"** https://github.com/orgs/linkml/discussions/3813 (Silvano Cirujano Cuesta; Nico Matentzoglu in support)
- **https://github.com/linkml/linkml/pull/3811** (open): `required` plus `value_presence: UNCOMMITTED` allows null in JSON Schema.
  - Tested from the PR head: null with no reason passes; null with a reason fails once rules are added, because null counts as PRESENT.
  - Pydantic still rejects None.
- `main`, unreleased: optional enum slots accept null; `gen-json-schema --no-include-null`.
- LinkML-Map `missing_values` turns sentinel codes (-9, 999) into null: the reason is dropped by design.
- Still open: https://github.com/linkml/linkml/issues/178 (since 2021), https://github.com/linkml/linkml/issues/1994

## Not every gap is missing data

| Case | What it really is | Where it belongs |
|---|---|---|
| does not apply | a fact about the schema | `value_presence: ABSENT`, not a sentinel in every row |
| "other" | a real value outside the value set | value-set coverage (HL7 puts OTH under **invalid**) |
| below detection | a bounded value | min/max value, not a reason |
| lost in transit, deleted, offline | a fact about the dataset or pipeline | a separate record (option 4), provenance, validation report |

## Questions for OBI

1. Should new incomplete-data classes extend or align with **GENEPIO:0001850 datum status**?
2. Is "other" incomplete at all, or a value outside the permitted set?
3. Where do lifecycle states (in process, deleted, offline) belong: IAO, OBI, or provenance?
4. Should "asked, answer was unknown" and "declined" be distinct terms?
5. Could MIxS and LinkML value sets point `meaning:` at these terms once they have PURLs?
