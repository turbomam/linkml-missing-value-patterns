## The case: Napoleon's height

- Estimated at **5 feet 2 inches in pre-metric French measures, about 1.67 m**. Other historians give **1.70 m**.
- Read as English inches, 62 inches is **1.5748 m**. The value existed, was recorded, and was lost in translation.
- The cartoonist James Gillray popularized the myth that he was short.

Source: English Wikipedia, ["Napoleon complex"](https://en.wikipedia.org/wiki/Napoleon_complex), read 2026-09-14.

Everything else here is an **imagined archive** ([`napoleon/data`](https://github.com/turbomam/linkml-missing-value-patterns/tree/slides-obi-2026-09-14/napoleon/data), [`rdf-examples`](https://github.com/turbomam/linkml-missing-value-patterns/tree/slides-obi-2026-09-14/rdf-examples)) about Napoleon's body and relics: examination records, witness reports, hair locks, lab controls. The records are invented to give every kind of missing value one concrete case.

## Two stacks, two instincts

| | Same fact: a person who must have a height has none recorded |
|---|---|
| OWL reasoner (HermiT, ROBOT 1.9.10) | **consistent**: the height exists, nobody wrote it down |
| SHACL (pyshacl 0.40.1, `sh:minCount 1`) | **does not conform** |
| LinkML (`linkml-validate`, `required: true`) | **error**: `'height_m' is a required property` |

- OWL can refuse a value that must **not** be there: a hair lock with a height is inconsistent.
- OWL toolchains rarely refuse a **missing** value, so OBO's strength is **explaining** why it is missing.
- LinkML validates at the door, so its strength is **refusing** a silent gap, and its question is how to let an explanation through.

Run: `just open-world`. Files: [`required_height.ofn`](https://github.com/turbomam/linkml-missing-value-patterns/blob/slides-obi-2026-09-14/napoleon/demos/open_world/required_height.ofn), [`forbidden_height.ofn`](https://github.com/turbomam/linkml-missing-value-patterns/blob/slides-obi-2026-09-14/napoleon/demos/open_world/forbidden_height.ofn), [`shapes.ttl`](https://github.com/turbomam/linkml-missing-value-patterns/blob/slides-obi-2026-09-14/napoleon/demos/open_world/shapes.ttl), [`data.ttl`](https://github.com/turbomam/linkml-missing-value-patterns/blob/slides-obi-2026-09-14/napoleon/demos/open_world/data.ttl), [`strict.yaml`](https://github.com/turbomam/linkml-missing-value-patterns/blob/slides-obi-2026-09-14/napoleon/schema/strict.yaml)

## The OBI draft, applied to the archive

<!-- _class: small -->

Sebastian Duesing's "Incomplete Data Items", revised hierarchy v2, unchanged since 2026-08-31. Definitions paraphrased.

```
data record
  incomplete data record          no data entity is stored
    missing data record           could fit the record, but no value is stored
      not available data record   may have been determined, not available      -> descendant's height, withheld
      unknown data record         not determined                               -> height at birth
    not applicable data record    does not make sense                          -> reagent blank, hair lock
  other data record               outside the allowed options                  -> a period unit not in the unit list
  syntactically incorrect record  (definition not yet written)                 -> 5'2" in a numeric field
```

Not placed yet: an answer of "unknown", a declined measurement, a failed measurement, a value lost in transit.

## In OBO RDF: three alternative files for one height

<!-- _class: small -->

Three separate files, each loaded with the same [`base.ttl`](https://github.com/turbomam/linkml-missing-value-patterns/blob/slides-obi-2026-09-14/rdf-examples/base.ttl): [`p00_complete.ttl`](https://github.com/turbomam/linkml-missing-value-patterns/blob/slides-obi-2026-09-14/rdf-examples/p00_complete.ttl), [`p03_reason_as_term.ttl`](https://github.com/turbomam/linkml-missing-value-patterns/blob/slides-obi-2026-09-14/rdf-examples/p03_reason_as_term.ttl), [`p04_value_node_without_value.ttl`](https://github.com/turbomam/linkml-missing-value-patterns/blob/slides-obi-2026-09-14/rdf-examples/p04_value_node_without_value.ttl). Alternatives, not steps.

```turtle
# p00_complete.ttl: the height is recorded
ex:heightAssay1 a OBI:0003817 ;                 # length measurement assay
    OBI:0000293 ex:napoleon ; OBI:0000299 ex:heightDatum1 .
ex:heightDatum1 a IAO:0000109 ; IAO:0000136 ex:napoleonHeight ; OBI:0001938 ex:valueSpec1 .
ex:valueSpec1 a OBI:0001931 ; OBI:0001937 "1.67"^^xsd:decimal ; IAO:0000039 UO:0000008 .

# p03_reason_as_term.ttl, instead: a reason where the value specification belongs (height at birth)
ex:heightDatum1 OBI:0001938 ex:reason1 .
ex:reason1 a GENEPIO:0001620 .                  # not collected

# p04_value_node_without_value.ttl, instead: the value node keeps its unit, has no number, and a status is about it
ex:valueSpec1 a OBI:0001931 ; IAO:0000039 UO:0000008 .
ex:status1 a GENEPIO:0001668 ; IAO:0000136 ex:valueSpec1 .    # not provided
```

p03 puts a status where OBI expects a value specification; p04 keeps the unit of what was not measured.

Terms: [OBI:0003817](https://www.ebi.ac.uk/ols4/ontologies/obi/classes/http%253A%252F%252Fpurl.obolibrary.org%252Fobo%252FOBI_0003817) length measurement assay, [OBI:0000293](https://www.ebi.ac.uk/ols4/ontologies/obi/properties/http%253A%252F%252Fpurl.obolibrary.org%252Fobo%252FOBI_0000293) has specified input, [OBI:0000299](https://www.ebi.ac.uk/ols4/ontologies/obi/properties/http%253A%252F%252Fpurl.obolibrary.org%252Fobo%252FOBI_0000299) has specified output, [IAO:0000109](https://www.ebi.ac.uk/ols4/ontologies/iao/classes/http%253A%252F%252Fpurl.obolibrary.org%252Fobo%252FIAO_0000109) measurement datum, [IAO:0000136](https://www.ebi.ac.uk/ols4/ontologies/iao/properties/http%253A%252F%252Fpurl.obolibrary.org%252Fobo%252FIAO_0000136) is about, [OBI:0001938](https://www.ebi.ac.uk/ols4/ontologies/obi/properties/http%253A%252F%252Fpurl.obolibrary.org%252Fobo%252FOBI_0001938) has value specification, [OBI:0001931](https://www.ebi.ac.uk/ols4/ontologies/obi/classes/http%253A%252F%252Fpurl.obolibrary.org%252Fobo%252FOBI_0001931) scalar value specification, [OBI:0001937](https://www.ebi.ac.uk/ols4/ontologies/obi/properties/http%253A%252F%252Fpurl.obolibrary.org%252Fobo%252FOBI_0001937) has specified numeric value, [IAO:0000039](https://www.ebi.ac.uk/ols4/ontologies/iao/properties/http%253A%252F%252Fpurl.obolibrary.org%252Fobo%252FIAO_0000039) has measurement unit label, [UO:0000008](https://www.ebi.ac.uk/ols4/ontologies/uo/classes/http%253A%252F%252Fpurl.obolibrary.org%252Fobo%252FUO_0000008) meter, [GENEPIO:0001620](https://www.ebi.ac.uk/ols4/ontologies/genepio/classes/http%253A%252F%252Fpurl.obolibrary.org%252Fobo%252FGENEPIO_0001620) not collected, [GENEPIO:0001668](https://www.ebi.ac.uk/ols4/ontologies/genepio/classes/http%253A%252F%252Fpurl.obolibrary.org%252Fobo%252FGENEPIO_0001668) not provided

## LinkML patterns, in plain words

<!-- _class: small -->

- **[strict](https://github.com/turbomam/linkml-missing-value-patterns/blob/slides-obi-2026-09-14/napoleon/schema/strict.yaml)**: the height must be a number. A record without one is refused, and so is `5'2"`. There is nowhere to say why a height is missing.
- **[union](https://github.com/turbomam/linkml-missing-value-patterns/blob/slides-obi-2026-09-14/napoleon/schema/union.yaml)** and **[one-of](https://github.com/turbomam/linkml-missing-value-patterns/blob/slides-obi-2026-09-14/napoleon/schema/one_of.yaml)**: the height may be a number or an INSDC term such as `not collected`. The field stays required, but it is no longer always a number, and the record cannot be written as a table or as RDF.
- **[value-object](https://github.com/turbomam/linkml-missing-value-patterns/blob/slides-obi-2026-09-14/napoleon/schema/value_object.yaml)**: the height is a small object holding either a number with its unit, or a reason. The field stays required and the number stays a number; the table gets one column per part of the object.
- **[reason-column](https://github.com/turbomam/linkml-missing-value-patterns/blob/slides-obi-2026-09-14/napoleon/schema/reason_column.yaml)**: the height stays an optional number, and a second column holds the reason. Rules require exactly one of the two. It flattens to a table and converts to RDF, where the reason becomes an ontology term.
- **[side-report](https://github.com/turbomam/linkml-missing-value-patterns/blob/slides-obi-2026-09-14/napoleon/schema/side_report.yaml)**: records hold only real values, and a separate report says which value is missing and why. It is the only place to say a pipeline lost a value, but no rule can check that every gap has a report.
- **[not-applicable](https://github.com/turbomam/linkml-missing-value-patterns/blob/slides-obi-2026-09-14/napoleon/schema/not_applicable.yaml)**: the schema, not the data, says a hair-lock record has no height (`value_presence: ABSENT`).

Two features that sound relevant do less than their names suggest. `recommended: true` reports nothing unless `RecommendedSlotsPlugin` is configured (`just recommended`). `ifabsent` fills a default only in generated Python and Pydantic classes, not during validation (`just ifabsent`). Demo schemas: [`recommended.yaml`](https://github.com/turbomam/linkml-missing-value-patterns/blob/slides-obi-2026-09-14/napoleon/demos/recommended.yaml), [`ifabsent.yaml`](https://github.com/turbomam/linkml-missing-value-patterns/blob/slides-obi-2026-09-14/napoleon/demos/ifabsent.yaml). Shared value sets: [`common.yaml`](https://github.com/turbomam/linkml-missing-value-patterns/blob/slides-obi-2026-09-14/napoleon/schema/common.yaml).

## Backup: what is moving in LinkML

- **"Are required slots nullable?"** https://github.com/orgs/linkml/discussions/3813
- **https://github.com/linkml/linkml/pull/3811** (open): `required` plus `value_presence: UNCOMMITTED` allows null in JSON Schema. A null still counts as present inside rules, so "null plus a reason" is refused.
- No LinkML condition can test for null.
- `value_presence` is marked unstable; `gen-owl` ignores it in rules.
- LinkML-Map `missing_values` turns sentinel codes into null and drops the reason.
- Still open: https://github.com/linkml/linkml/issues/178 (since 2021)
