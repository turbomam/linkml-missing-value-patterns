## The case: Napoleon's height

- Estimated at **5 feet 2 inches in pre-metric French measures, about 1.67 m**. Other historians give **1.70 m**.
- Read as English inches, 62 inches is **1.5748 m**. The value existed, was recorded, and was lost in translation.
- The cartoonist James Gillray popularized the myth that he was short.

Source: English Wikipedia, "Napoleon complex", read 2026-09-14.

Everything else here is an **imagined archive** about Napoleon's body and relics: examination records, witness reports, hair locks, lab controls. The records are invented to give every kind of missing value one concrete case.

## Two stacks, two instincts

| | Same fact: a person who must have a height has none recorded |
|---|---|
| OWL reasoner (HermiT, ROBOT 1.9.10) | **consistent**: the height exists, nobody wrote it down |
| SHACL (pyshacl 0.40.1, `sh:minCount 1`) | **does not conform** |
| LinkML (`linkml-validate`, `required: true`) | **error**: `'height_m' is a required property` |

- OWL can refuse a value that must **not** be there: a hair lock with a height is inconsistent.
- OWL toolchains rarely refuse a **missing** value, so OBO's strength is **explaining** why it is missing.
- LinkML validates at the door, so its strength is **refusing** a silent gap, and its question is how to let an explanation through.

Run: `just open-world`

## Ways a height can be missing

<!-- _class: small -->

| Kind | Archive record (invented) | Terms that name it |
|---|---|---|
| never measured | height at birth | INSDC / GENEPIO not collected; HL7 NASK |
| not provided yet | museum has not released a record | GENEPIO:0001668 not provided |
| withheld | a living descendant's height | GENEPIO:0001810 restricted access; INSDC human-identifiable |
| does not apply | a lab reagent blank; a hair-lock record | INSDC not applicable: control sample; GENEPIO:0001619 |
| reported, not measured | height taken from a memoir | INSDC missing: third party data |
| asked, answer "unknown" | a witness asked his height | NCIT:C79729 Asked but Unknown; FHIR asked-unknown |
| asked, declined | the subject declined to be measured | NCIT:C51024 Response Declined; FHIR asked-declined |
| written wrongly | `5'2"` in a numeric field | OBI draft: syntactically incorrect record |
| two sources disagree | 1.67 m and 1.70 m | not missing: a range |
| measurement failed | a measurement attempt with no datum | COB:0000083 failed planned process |
| lost in transit | 62 French inches read as English inches | no term in INSDC, GENEPIO or HL7 |
| in process | an analysis queued, not finished | GENEPIO:0001662 in process |

## The OBI draft, applied to the archive

<!-- _class: small -->

Sebastian Duesing's "Incomplete Data Items", revised hierarchy v2, unchanged since 2026-08-31. Definitions paraphrased.

```
data record
  incomplete data record          no data entity is stored
    missing data record           could fit the record, but no value is stored
      not available data record   may have been determined, not available      -> descendant's height, withheld
      unknown data record         not determined                               -> height at birth
    not applicable data record    does not make sense                          -> reagent blank, hair lock
  other data record               outside the allowed options                  -> a period unit not in the unit list
  syntactically incorrect record  (definition not yet written)                 -> 5'2" in a numeric field
```

Not placed yet: an answer of "unknown", a declined measurement, a failed measurement, a value lost in transit.

## In OBO RDF: a value, a reason, a value node

<!-- _class: small -->

```turtle
# p00 recorded
ex:heightAssay1 a OBI:0003817 ;                 # length measurement assay
    OBI:0000293 ex:napoleon ; OBI:0000299 ex:heightDatum1 .
ex:heightDatum1 a IAO:0000109 ; IAO:0000136 ex:napoleonHeight ; OBI:0001938 ex:valueSpec1 .
ex:valueSpec1 a OBI:0001931 ; OBI:0001937 "1.67"^^xsd:decimal ; IAO:0000039 UO:0000008 .

# p03 a reason where the value specification belongs (height at birth)
ex:heightDatum1 OBI:0001938 ex:reason1 .
ex:reason1 a GENEPIO:0001620 .                  # not collected

# p04 the value node keeps its unit and has no number; a status is about it
ex:valueSpec1 a OBI:0001931 ; IAO:0000039 UO:0000008 .
ex:status1 a GENEPIO:0001668 ; IAO:0000136 ex:valueSpec1 .    # not provided
```

p03 puts a GENEPIO status where OBI's range for OBI:0001938 expects a value specification. p04 keeps what would have been measured, and in which unit.

## In OBO RDF: failed, not applicable, lost, never measured

<!-- _class: small -->

| Pattern | Triples | HermiT |
|---|---|---|
| p02 written wrongly | `OBI:0001937 "5'2\""` | **inconsistent** (`owl:real` range) |
| p05 measurement failed | `a COB:0000083` failed planned process, participants only, no output | consistent; giving it `has specified input` is inconsistent |
| p06 does not apply | a hair-lock record allows exactly 0 length measurement assays | consistent; adding one is inconsistent |
| p09 lost in transit | PROV-O activity on the dataset; the examination record is untouched | consistent |
| p10 never measured | negative property assertion or complement class on the examination | consistent; adding one is inconsistent |
| p12 answer "unknown" | witness report datum typed NCIT:C79729 | consistent |

**Gaps found:** no OBO relation from a datum status to its datum (IAO:0000136 is about was used); no OBI body height assay (OBI:0003817 length measurement assay used); no OBO term for a deliberate "unknown" answer; failed assays are open in https://github.com/obi-ontology/obi/issues/1230

Run: `just rdf` (each SPARQL query finds its pattern and nothing in p00; HermiT on every merged file)

## In LinkML YAML: refuse, or accept a reason

<!-- _class: small -->

```yaml
# strict: refused ('5\'2"' is not of type 'number')
record_id: REC:0003
height_m: "5'2\""
```

```yaml
# union: a float or an INSDC term (any_of); accepted
record_id: REC:0102                    # a reagent blank
height_m: "not applicable: control sample"
```

```yaml
# reason-column: height_m stays a float; a rule requires a reason when it is absent; accepted
record_id: REC:0402
height_m_missing_reason: asked, answer unknown     # meaning NCIT:C79729
```

```yaml
# side-report: the record stays plain; the dataset explains
missing_value_reports:
  - about_record: REC:0501
    about_slot: height_m
    report_reason: lost in transit
```

Run: `just strict`, `just union`, `just reason-column`, `just side-report`

## LinkML patterns and features

<!-- _class: small -->

| `just` recipe | Shape | Stays required | Keeps float | Flat table |
|---|---|---|---|---|
| `strict` | no escape hatch | yes | yes | yes |
| `union` / `one-of` | float or reason, `any_of` / `exactly_one_of` | yes | no | no (cannot convert) |
| `value-object` | an object holding a number or a reason | yes | yes | yes, flattened |
| `reason-column` | optional float plus a reason column, tied by rules | via rules | yes | yes, +1 column |
| `side-report` | separate records explain the gaps | no | yes | yes, two tables |
| `not-applicable` | `value_presence: ABSENT` on a hair-lock record | forbidden there | n/a | Turtle yes |

| Feature | What it does with a missing value | Run |
|---|---|---|
| `recommended: true` | nothing by default; a warning with `RecommendedSlotsPlugin` | `just recommended` |
| `ifabsent: string(m)` | generated Pydantic fills the unit; validation and JSON Schema do not | `just ifabsent` |
| `inapplicable` | implemented nowhere | |

`just check` runs every pattern: valid records must pass, invalid ones must fail (linkml 1.11.1).

## One record, three formats

<!-- _class: small -->

YAML, as submitted (reason-column):

```yaml
record_id: REC:0402
height_m_missing_reason: asked, answer unknown
source_type: memoir
```

TSV (`linkml-convert -t tsv`): the label stays a label

```
record_id  height_m_missing_reason  source_type  height_m
REC:0402   asked, answer unknown    memoir
REC:0401                            physical     1.67
```

Turtle (`linkml-convert -t ttl`): the label becomes the term

```turtle
REC:0402 a nap:HeightRecord ;
    nap:height_m_missing_reason NCIT:C79729 ;
    nap:source_type "memoir" .
```

The union record `height_m: "not applicable: control sample"` cannot be written as either: `Not a valid CURIE`. Run: `just tables`

## Questions for OBI

1. OWL explains, LinkML refuses: which one should carry the reason, or both?
2. Should incomplete-data classes extend or align with **GENEPIO:0001850 datum status**?
3. Is "other" incomplete at all, or a value outside the permitted set?
4. Where do "answer was unknown" and "declined" belong, since INSDC and GENEPIO have neither?
5. Which relation should connect a datum status to the datum it explains?
6. Where do "lost in transit" and "in process" belong: IAO, OBI, or provenance?

## Backup: what is moving in LinkML

- **"Are required slots nullable?"** https://github.com/orgs/linkml/discussions/3813
- **https://github.com/linkml/linkml/pull/3811** (open): `required` plus `value_presence: UNCOMMITTED` allows null in JSON Schema. A null still counts as present inside rules, so "null plus a reason" is refused.
- No LinkML condition can test for null.
- `value_presence` is marked unstable; `gen-owl` ignores it in rules.
- LinkML-Map `missing_values` turns sentinel codes into null and drops the reason.
- Still open: https://github.com/linkml/linkml/issues/178 (since 2021)

## Backup: every query against every file

<!-- _class: small -->

```
query / data   p00 p01 p02 p03 p04 p05 p06 p07 p08 p09 p10 p11 p12
p00 complete   [1]  .   .   .   .   .   .   .   .   1   .   .   .
p01 nothing     .  [1]  .   1   .   .   1   1   .   .   .   .   1
p02 ... p12    only their own file (diagonal)
```

- **p00 matches p09.** The lost-in-transit file stores `1.5748` m as an ordinary numeric value with a unit; only a separate SHACL report flags it. A query for a complete measurement cannot tell a correct value from a mis-converted one.
- **p01 matches p03, p06, p07, p12.** Those files attach their facts to other records, so the shared examination has no parts. "Nothing asserted" is a question about the graph, not about Napoleon: in an open world it cannot be told apart from "not mentioned here".

Run: `just rdf-matrix` (13 x 13; the diagonal must match, off-diagonal hits are listed)
